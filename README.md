# Narrate (text-to-audiobook)

Turn text you find (a pasted thread, an article, a PDF, an EPUB, a screenplay) into a multi-voice audiobook with a read-along reader that highlights each word as it's spoken.

**Live showcase:** https://text-to-audiobook-blond.vercel.app: one pre-recorded public-domain story (O. Henry's *The Gift of the Magi*, 4 voices, 12 min) with the real reader and player. Importing and recording run on your own computer ([Run locally](#run-locally)).

| Import quality, measured on 9 messy formats with a known right answer | Before the Nov 2026 revive | Now |
|---|---|---|
| Chapter and sub-headings found | 14/36 (6 formats) | 49/54 rules only · **54/54** with the optional AI second opinion |
| Paragraphs reproduced exactly | 66.7% | **100%** |
| Junk read aloud (licences, contents pages, running headers, references, "Show more") | 20 | 5 rules only (one deliberately hard case) · **0** with the second opinion |
| Real words lost | 0 | **0** |
| Formats | paste, .txt, .md, PDF, web link | + **EPUB**, Gutenberg files, typeset book PDFs, X threads |

Generated by `python -m structure_eval` ([reports/structure-eval.md](services/api/reports/structure-eval.md)). Every option we tried, chose or rejected, and why, is in the [decision log](docs/decision-log.md).

## How it works

```
paste · .txt/.md · PDF · EPUB · web link
        │
        ▼
 ingest ─► cleanup ─► structure ─► (optional) AI second opinion ─► saved book
 pypdf     licence,    paragraphs,    only short doubtful lines,      Postgres
 EPUB→md   contents,   headings,      e.g. "Show more" or a
 trafilat. references  bylines        sentence-case chapter title
        │
        ▼
 AI director (Gemini, Groq fallback): genre, cast, then every line's speaker, emotion, pace, pauses
        │
        ▼
 casting: each character → a Kokoro voice ("personas", editable; never a real person's voice)
        │
        ▼
 recording (Kokoro-82M, local CPU) → clip cache → one MP3 + word-timing manifest per chapter
        │
        ├─► read-along reader: word highlighting, tap-to-seek, 4 highlight styles, speeds
        ├─► Ask AI side panel: answers about the book "so far" (no spoilers)
        └─► export: M4B or MP3 with chapter markers
```

**Why these choices**

- **Rules first, AI second.** Structure is found by deterministic rules: free, instant, private, and they never delete text. In the revive, an AI labelling every line was measured to be *worse* (it called running headers chapter titles), so the AI only gets the few lines the rules can't decide ([decision log §3](docs/decision-log.md)).
- **One pipeline for every format.** PDF and EPUB are turned into text or markdown first, so every cleanup rule (Gutenberg licence, contents pages, back matter, author checks) applies to all of them.
- **A measurement harness before any fix.** Each format is rendered from a synthetic book, so the right answer is known exactly, and every change shows its before and after.
- **Free by default.** Local Kokoro voices; a free Gemini key you bring yourself; Groq (free) takes over when Gemini is overloaded. Narrate runs on your computer, because no free host without a card can run the voice engine.
- **One data model** (sections → blocks → segments): parsing, directing, recording and reading are separate stages that can each be re-run; editing one line re-records only that line.

## Inputs (no dataset)

Narrate has no training data; it reads whatever you give it. The import evaluation uses **synthetic** books only (`services/api/structure_eval/`, written for the tests), so no copyrighted text is in the repo. Real-world checks used public-domain Project Gutenberg books and a Wikipedia article, downloaded to a scratch folder and never committed. The showcase story is public domain.

## Results

**Import on real inputs** (all measured in the revive, Nov 2026):

| Input | Before | After |
|---|---|---|
| *Sherlock Holmes* from Project Gutenberg (.txt, 104k words) | 0 of 12 stories found; ~3,100 licence words read aloud | **12/12** stories, right title and author, **0** licence words |
| A 60-page typeset book PDF (real prose, known truth) | **0/611** paragraphs right, running headers read | **610/611** paragraphs, 7/7 headings, 0 of 24,889 words lost |
| A Wikipedia article (URL import) | References (~38% of words) read; junk metadata as author | 1,974 → 1,212 spoken words; author check rejects the junk |
| A plot thread copied from X | "Act One:" glued into the text; "Post-Credits Scene:" missed | all 4 acts found |
| *Sherlock Holmes* as EPUB | not supported | **12/12** stories, licence skipped |

**The AI second opinion** (optional, off by default): on the 8 normal test formats it is never called (0 doubtful lines). On a deliberately hard X thread (sentence-case chapter titles, "Show more", view counts) it lifts headings from 1/6 to 6/6 (Gemini 3.5 Flash-Lite) or 5/6 (Claude Haiku 5.5), with 0 junk and 0 words lost, for ~350–700 input tokens per import (≈ $0.00007 on Claude Haiku 5.5).

## Project structure

```
apps/web/                 Next.js app (App Router, TypeScript, Tailwind, Motion)
  src/app/                pages: home, new book, library, director's notes, reader
  src/components/         reader, player bar, Ask AI panel, director's notes, library
  src/lib/api.ts          typed client for the API (all calls go through /api)
  src/lib/demo.ts         the showcase switch (NEXT_PUBLIC_DEMO=1)
  public/demo/            the showcase book: a snapshot of API responses + one MP3
  next.config.ts          /api proxy to FastAPI, or to public/demo in the showcase
services/api/             FastAPI backend
  app/ingest/             paste/file/URL/PDF/EPUB → text (epub.py, pdf.py, url.py)
  app/structure/          cleanup.py (licences, contents, references), prose.py (paragraphs,
                          headings), screenplay.py, second_opinion.py (optional AI)
  app/director/           the AI director: genre, cast, per-line performance labels
  app/render/             recording jobs, clip cache, chapter MP3s and manifests, export
  app/tts/                Kokoro voice engine
  app/ask/                Ask AI (streamed answers about the book so far)
  structure_eval/         import-quality harness: synthetic book → 9 messy formats → scores
  reports/                structure-eval.md and its history (generated)
  tests/                  pytest
scripts/
  setup.sh                one-time setup (checks tools, .env, database, dependencies)
  start.sh                run the API + web app; --phone opens it to your Wi-Fi
  export_showcase.py      snapshot one recorded book for the showcase
docs/                     decision log, design system, narration guide, screenshots
```

## Run locally

Needs macOS or Linux with Node 20+, [uv](https://docs.astral.sh/uv/) (it fetches Python 3.11/3.12 itself), Postgres 14+, ffmpeg and espeak-ng. On a Mac: `brew install uv node postgresql@14 ffmpeg espeak-ng && brew services start postgresql@14`.

```bash
./scripts/setup.sh
```

Then add a free Gemini key ([aistudio.google.com](https://aistudio.google.com)) to `services/api/.env` as `GEMINI_API_KEY=…`, and start it:

```bash
./scripts/start.sh
```

Open http://localhost:3000. To use it from your phone on the same Wi-Fi:

```bash
./scripts/start.sh --phone
```

It prints the address to open (like `http://192.168.1.20:3000`). Narrate has no login, so this lets anyone on that network use it: fine at home, not on public Wi-Fi. The first recording downloads the Kokoro voice model (~330 MB).

**Optional settings** (`services/api/.env`, all listed in `.env.example`): `GROQ_API_KEY` for the fallback director, `STRUCTURE_AI=gemini` or `claude` (+ `ANTHROPIC_API_KEY`) for the AI second opinion at import.

**Developing** (auto-reload, two terminals):

```bash
cd services/api && uv run --no-sync uvicorn app.main:app --reload --port 8000
```
```bash
cd apps/web && npm run dev
```

**Tests and checks**

```bash
cd services/api && uv run --no-sync pytest -q -m "not live"
```
```bash
cd services/api && uv run --no-sync python -m structure_eval
```
```bash
cd apps/web && npm test && npx tsc --noEmit && npx eslint src
```

The structure evaluation prints the scores table; `--label "<name>"` records a run in the history and `--ai gemini|claude` scores the second opinion (that calls the provider).

## Deployment

- **The app runs locally** by design: the voice engine (Kokoro + PyTorch) needs ~1–2 GB of RAM, and every free host checked in Nov 2026 either can't run it (Render's free tier: 512 MB, 0.1 CPU) or needs a paid plan or a card (Hugging Face CPU Spaces now need PRO; Fly.io, Oracle, Google Cloud need a card). Details in the [decision log](docs/decision-log.md).
- **The showcase** is the same Next.js app on Vercel's free Hobby plan: root directory `apps/web`, environment variable `NEXT_PUBLIC_DEMO=1`. In that build the read-only `/api/...` calls are answered from `apps/web/public/demo/`, and anything that would write explains that it's a showcase. Every push to `main` redeploys it.
- **To change the showcase book:** record it in the local app, run `python3 scripts/export_showcase.py <document-id>` with the API running, update `SHOWCASE_BOOK` in `apps/web/src/lib/demo.ts`, commit. Public-domain text only.
- **Pinned:** `services/api/uv.lock` and `.python-version` (Python 3.11–3.12; Kokoro doesn't support 3.13), `apps/web/package-lock.json` (Next.js 16.4).

## Limitations

- **Narrate's limits are mostly budget and hardware limits.** A $0 budget with no card means no hosted voice engine or GPU, free LLM tiers (Gemini Flash: 20 requests/day; frequent "high demand" errors), and recording on one laptop CPU at ~2.5–3.7× real time. The [decision log §1](docs/decision-log.md) lists what each constraint cost and what we'd do without it.
- **Kokoro has no emotion control**: "acting" comes from casting, pace, pauses and emphasis.
- **Import:** scanned PDFs need OCR (not supported); in a PDF with neither indents nor blank lines, a paragraph whose last line is nearly full width can't be split; DRM-protected EPUBs can't be read; a short Title Case line ending in ":" (a letter's "Dear Sir:") can become a sub-heading; non-fiction sidebars in EPUBs are skipped with footnotes.
- **The structure evaluation is synthetic** apart from the real-input checks above; books with layouts it doesn't cover are the real risk.
- **Single user, no login, no CI.** Books imported before the revive keep their old structure until re-imported.

## Learning log: mistakes and what I learned

I built Narrate in two layers: a fast feature build, then a revive that measured everything. Each row is what went wrong (with evidence) and the lesson.

### Layer 1: the build (28 Oct – 1 Nov 2026, Claude Code, Next.js + FastAPI, Gemini, Kokoro)

*What I built:* a local-only proof of concept in 16 reviewed PRs: import, an AI director that casts voices and labels every line, local recording, a read-along reader, Ask AI and export.

| # | Mistake | What actually happened | Lesson |
|---|---|---|---|
| 1.1 | **Structure was an afterthought** | The parser only knew markdown headings and a "CHAPTER" regex. *Sherlock Holmes* from Gutenberg came out as 0 of 12 stories, cut into 69 arbitrary parts, with ~3,100 licence words read aloud; a typeset PDF got 0/611 paragraphs right. | The first stage decides the quality of everything after it. Test the input stage on real, messy inputs first. |
| 1.2 | **No way to measure formatting** | Formatting was judged by reading output, so I couldn't tell whether a fix helped or what it broke. | Build the evaluation (with known answers) before the fixes. |
| 1.3 | **Trusting metadata** | A PDF's title came out as "Microsoft Word - All Tomorrows.doc"; a Wikipedia page's "author" was "Authority control databases…". | Data from someone else's file or page is input to validate, not truth. |
| 1.4 | **Free-tier limits found late** | Gemini Flash's free tier allows 20 requests a day (live 429 error), and overload errors left 300 of 1,053 lines on default delivery for one book. | Check quotas and failure modes of free tiers before designing around them; plan retries and a fallback. |
| 1.5 | **Verbose AI output** | Pretty-printed JSON labels cost ~80 output tokens per line; compact rows (`12\|MARA\|anxious\|…`) cost ~23 (fixed in PR 16). | Output tokens are the slow and expensive part; design compact output formats. |
| 1.6 | **One huge chapter** | *All Tomorrows* imported as one 56-minute chapter, so nothing played until all of it was recorded (fixed in PR 14 with ~10-minute parts). | Design for time-to-first-value, not just the finished result. |
| 1.7 | **Never installed it from scratch** | The committed web lockfile had drifted from package.json, so `npm ci` (what a fresh clone or CI runs) refused to install; it only worked on my machine because `npm install` quietly repairs drift. | "Works on my machine" isn't verified: test a clean clone. |
| 1.8 | **Laptop-only, phone-first goal** | Most listening happens on a phone, but nothing was deployable or reachable from one. | Decide early where the product actually runs, and check the hosting constraints (RAM, cost, cards) before building around them. |

### Layer 2: the revive (Nov 2026)

*What I did:* measured the formatting problem, compared AI cleanup against better rules, rebuilt import for every format (adding EPUB), and made it runnable by anyone plus a free public showcase, one verified commit at a time.

| # | Decision | Why |
|---|---|---|
| 2.1 | A structure-eval harness first (synthetic book → 9 messy formats, known answers) | Fixes 1.2; every later step has a before/after number. |
| 2.2 | Better deterministic rules over AI labelling of every line | Measured: AI-labels-everything scored worst on the PDF (78% paragraphs, 114 junk lines); rules scored 611/611 at 0 tokens (1.1). |
| 2.3 | Cleanup before parsing: Gutenberg licence, contents pages, back matter | Junk removed once means no later stage has to know about it (1.1). |
| 2.4 | Strong vs weak headings, two passes; explicit headings beat guessing | Bare-word chapter titles work, and a short paragraph in an EPUB stays a paragraph. |
| 2.5 | PDF header slots and paragraph indents | Running headers that change per chapter and indent-only paragraphs are how real books are typeset (PDF: 0/611 → 610/611). |
| 2.6 | Validate titles and authors from metadata | Fixes 1.3. |
| 2.7 | Native EPUB import, standard library only; my text → EPUB → import idea rejected | The converter's EPUB had no headings and dropped "&" and an emoji; real EPUBs already carry structure. |
| 2.8 | An optional AI second opinion on doubtful lines only, off by default | Helps on messy X threads (1/6 → 6/6 headings) at ~$0.00007; never called on normal books. A real false positive (a bullet point called a chapter title) was fixed by giving the model context on both sides. |
| 2.9 | Run locally with one command; `--phone` for the Wi-Fi; a static showcase on Vercel | No free, card-less host can run the voice engine (1.8); the showcase is enough to show the product. |
| 2.10 | Verify from a fresh clone under macOS's bash 3.2 | Found the lockfile drift (1.7), a bash 3.2 syntax error, short pasted paragraphs being merged, and tests reading my own `.env`. |

*Known gaps I chose not to fix:* OCR for scanned PDFs, a phone app (PWA), paid or expressive voices, user accounts, CI, Docker, "Export as EPUB", re-importing old books, the pre-existing ruff warnings (FastAPI `Depends`).

### Key takeaways

1. **Measure before you fix.** A harness with known answers turned "it reads badly" into numbers, and caught my own regressions twice.
2. **Rules first, AI where rules can't decide.** The AI was cheap but not better; used only on doubtful lines, it added value without risking real text.
3. **Validate inputs you didn't write.** Metadata, page text and converter output all lied at least once.
4. **Test the way a stranger installs it.** A fresh clone found four bugs my machine had hidden.
5. **Most limits were the budget, not the design.** Writing down what each constraint cost makes the trade-offs explainable.

## Future improvements

- A phone app (PWA): home-screen install, offline books, lock-screen controls everywhere.
- Expressive voices (OpenAI gpt-4o-mini-tts or ElevenLabs) through the existing one-file engine interface.
